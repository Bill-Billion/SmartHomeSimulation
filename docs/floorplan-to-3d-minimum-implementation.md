作者：Bill Billion  
版本：v1.14  
日期：2026-03-31  
状态：当前唯一实现依据

---

## 1. 文档定位

本文档定义当前项目第一阶段的唯一实现基线。目标是让用户上传 CAD 或平面图后，系统完成规则解析、生成可预览 2D / 3D 场景，并在现有 Vue + TresJS 前端中立即展示结果。

第一阶段的主线已经从“只求链路跑通”推进到“默认规则结果足够可看，可选 AI 增强只补理解层”。多智能体运行时、复杂仲裁、回放、安全增强仍然保留为后续阶段能力，不进入当前实现边界。

阶段边界从本版开始明确调整：深度解释层不再作为阶段 1 的阻塞条件，改为阶段 2 并行项。

---

## 2. 第一阶段目标

第一阶段的用户闭环固定为：

用户上传 `JPG`、`PNG`、`PDF`、`DXF` 文件  
→ 后端转换为统一 `FloorplanSpec`  
→ 参数化生成 `SceneSpec` 和 `GLB`  
→ 前端轮询任务状态  
→ 任务完成后展示 2D 户型结构和 3D 场景预览

本阶段默认把 “CAD” 收敛为 `DXF` 一等支持。`DWG` 允许上传，但统一返回“请先转换为 DXF 或 PDF”的明确提示。

## 3. 系统边界

### 3.1 前端职责

- 提供上传面板
- 展示任务状态、warning 和错误提示
- 展示 2D 户型结构摘要
- 加载后端返回的 `GLB` 预览模型
- 提供默认视角、重置视角和基础高亮交互
- 提供默认关闭的 AI 辅助理解实验开关

前端不负责：

- 文件识别
- 几何建模
- 规则解析
- AI 结果裁决
- 资产生成

### 3.2 后端职责

- 接收上传文件
- 调度最小任务流程
- 解析图片 / PDF / DXF
- 生成统一 `FloorplanSpec`
- 生成 `SceneSpec`
- 导出 `GLB`
- 以文件系统保存产物并提供查询接口
- 在规则链之后按需执行 AI 理解增强

## 4. 输入与输出

### 4.1 输入格式

- `JPG`
- `PNG`
- `PDF`
- `DXF`

### 4.2 输出产物

- `job.json`：任务状态
- `floorplan.json`：统一户型结构
- `scene.json`：统一场景结构
- `model.glb`：前端预览模型

### 4.3 产物优先级

第一优先级是“可预览 3D 场景”。  
第一阶段不承诺：

- 可编辑 BIM 模型
- 成品级精装修效果
- 高质量导出施工模型
- 多楼层联动

## 5. 核心数据结构

### 5.1 FloorplanSpec

必须包含：

- 外墙线段
- 内墙线段
- 门窗开口
- 房间轮廓
- 识别置信度
- 源文件类型

### 5.2 SceneSpec

必须包含：

- 房间列表
- 墙体参数
- 门窗实例
- 地面与天花参数
- 基础家具实例
- 默认相机参数
- 资源版本号
- warning 列表

### 5.3 默认几何参数

- 单位：米
- 默认层高：`2.8m`
- 默认墙厚：`0.2m`
- 家具来源：内置模板

## 6. 实现策略

### 6.1 识别策略

图片和 PDF 走栅格识别管线：

- 先做线稿 / 彩色装修图样式识别
- 彩色装修图会先裁出主平面 ROI，再并行评估原始 ROI 和纹理压平 ROI
- 自适应二值化和结构墙提纯
- 墙线闭合增强
- 房间区域检测
- 用房间数量、最大房间占比、整图矩形退化和 warning 信号做质量评分，选出更可信的候选
- 正交轮廓保留，允许输出凹多边形
- 共享墙中心线归一
- 门窗剖面精修，检测失败时回退启发式结果

DXF 走结构化解析管线：

- 闭合 `LWPOLYLINE/POLYLINE` 会优先保留原始点序，不再先压成 bbox
- 开放 polyline 和纯 `LINE` 会先做端点吸附、同轴合并和正交单元格重建
- line-based `DXF` 会通过 flood fill 区分室内外，再追出房间 polygon，允许输出 `L` 形和多转折房间
- 恢复失败时只回退局部 bbox 或整图保守壳体，并通过 warning 明确说明原因
- `ARC`、`CIRCLE`、`SPLINE` 和非正交线段当前只记 warning，不参与房间几何恢复
- 归一到统一房间和墙体描述
- 共享墙中心线归一
- 复用同一套墙体与开口生成逻辑

当前房间语义判定固定为两段式：

- 先输出稳定的房间几何、墙体和开口
- 再叠加房间面积、外墙暴露、邻接关系、长宽比和紧凑度做语义打分
- 当没有 OCR / DXF 文本证据时，进入户型级全局一致性分配：按“走廊 → 客厅 → 厨房 → 卫生间 → 卧室”顺序选型，控制高稀缺类型容量，降低整图退化为 `generic` 的概率
- 栅格图会先从原图里减掉结构墙，再用 `Tesseract` 的 `eng+chi_sim` 语言包和 `--psm 11` 提取房间文字
- DXF 会读取 `TEXT`、`MTEXT`、`ATTRIB` 作为房间文字线索
- OCR 缺失、语言包不完整或执行失败时，只回退房间语义分类，不影响几何生成和预览链路

### 6.2 生成策略

参数化建模器当前按照统一规则生成：

- 地面按房间轮廓拉平
- 墙体按线段挤出
- 门窗按开口切分墙段
- 天花参与导出
- 门窗附加轻量构件，失败时回退为纯洞口
- 家具优先沿可用墙面摆放，失败时回退为居中摆放

当前 3D 可读性增强固定为：

- 默认保留房间分区色块
- 内外墙使用稳定差异色
- cutaway 墙按相机朝向选择，不再写死右侧和前侧
- 前端优先消费后端 `camera` 作为默认视角

### 6.3 当前内部结构边界

当前实现已经固定为 facade + 子模块的组织方式：

- `parsers.py` 只保留公开 facade 和兼容导出
- `parser_raster.py` 负责图片 / PDF 读取、样式路由、线稿分支、OCR 预处理和 raster 开口精修
- `parser_raster_decorated.py` 负责彩色装修图的主平面 ROI 裁剪、纹理压平、多策略房间恢复和候选裁决
- `parser_dxf.py` 负责 DXF 读取、单位缩放、文本锚点提取和 linework 编排
- `dxf_linework.py` 负责端点吸附、线段合并、正交单元格重建和 polygon 追边
- `floorplan_builder.py` 负责房间、墙体、开口、`FloorplanSpec` 装配，以及任意 polygon 的世界坐标居中
- `semantic_rules.py` 负责语义 hint 归一、语义打分、容量惩罚和 fallback
- `scene_builder.py` 只保留对外 facade
- facade 需要继续保留至少一个里程碑的兼容导出和旧签名 wrapper
- `scene_layout.py` 负责 `SceneSpec`、相机、cutaway 和家具摆放
- `scene_mesh.py` 负责 mesh 装配与 `GLB` 导出
- `App.vue` 只保留页面编排，上传、任务状态、场景摘要拆到独立组件，并在新任务开始时取消旧轮询和旧场景请求

### 6.4 房间类型范围

第一阶段只尝试输出：

- 卧室
- 客厅
- 厨房
- 卫生间
- 走廊

识别不确定时统一降级为通用房间，不中断生成流程。

### 6.5 阶段 1 实验增强

当前允许用户显式开启“AI 辅助理解（实验）”。

实验增强的边界固定为：

- 规则链先生成 `FloorplanSpec` 和草稿 `SceneSpec`
- AI 只允许返回 `room_overrides`、`furniture_hints`、`extra_warnings`
- AI 只能补房间语义修正、自然语言 warning 和家具贴墙建议
- AI 不能修改墙体、开口、房间轮廓和场景尺寸

当前实验增强只支持 OpenAI 兼容 chat completions 接口。前端收集 `llm_base_url`、`llm_model` 和 `llm_api_key`，后端统一走一个 adapter。密钥只在本次请求上下文里使用，不写入 `job.json`、`floorplan.json`、`scene.json`。

模型不可用、超时、返回非法 JSON、字段越界、配置缺失或证据不足时，系统必须回退到规则结果，并继续完成场景生成。

当前 AI 失败 warning 需要可诊断，至少会区分：

- 配置不完整
- 连接失败
- 请求超时
- 鉴权失败
- 接口路径不兼容
- 图片输入不支持
- 返回内容不是 JSON
- 返回结构不符合 schema

## 7. API

### 7.1 上传生成

`POST /api/floorplans:generate`

输入：

- multipart 必填字段：`file`
- multipart 可选字段：`llm_enabled`、`llm_base_url`、`llm_model`、`llm_api_key`

输出：`job_id`

### 7.2 查询任务

`GET /api/jobs/{job_id}`

输出：

- 任务状态
- 错误信息
- warning 列表
- 场景引用
- 模型引用

### 7.3 查询场景结构

`GET /api/scenes/{scene_id}`

输出：`SceneSpec`

### 7.4 获取预览模型

`GET /api/scenes/{scene_id}/model.glb`

输出：`GLB`

## 8. 验收标准

给定一张标准户型图或标准 DXF，前端上传后必须满足：

- 能看到任务进入处理中
- 任务完成后自动切换到新场景
- 场景中有地面、墙体、至少一个房间分区
- 2D / 3D 视图可以切换
- 3D 视图可以自由旋转、缩放并重置到默认视角

异常场景要求：

- 上传 `DWG` 时返回明确转换提示
- 识别质量差时允许降级，但不能中断
- AI 关闭时行为与规则版兼容
- AI 开启但失败时返回自然语言 warning，并继续生成规则结果
- 所有失败都必须返回自然语言错误说明

阶段 1 收口验收只看两类结果：

- 主闭环稳定：上传、解析、生成、2D/3D 预览和四个公开接口持续稳定
- 语义下限达标：无文本真实样本不出现大面积 `generic` 退化，核心房间类型分配满足结构化断言

深度解释层（diagnostics 接口与分析面板）不再作为阶段 1 的切换门槛。

## 9. 后续阶段

阶段 2 从本版开始按并行泳道推进。

运行时主线：

- 从 `SceneSpec` 派生 `WorldState`
- 初始化房间和基础设备位点
- 恢复 `SessionManager`
- 恢复 `ActionExecutor`
- 恢复单域 `LightingAgent` 最小闭环

可解释展示主线（并行，不阻塞运行时主线）：

- 新增 diagnostics 只读接口
- 新增源图预览接口（`DXF` 明确自然降级）
- 默认隐藏分析面板
- 2D/3D 证据联动与房间级聚焦

阶段 1 满足“主闭环稳定 + 语义下限达标”后即可进入阶段 2，不等待可解释展示主线先完成。
